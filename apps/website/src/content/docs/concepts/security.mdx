title: Security
description: What protects your files while the Localive dev server endpoint is running.
---

The dev server plugin exposes an endpoint that writes to your source files, so it only accepts requests that come from your own editor.

## Who Can Save

A save request is accepted only when it:

- **Comes from the dev server's own origin.** The browser's `Sec-Fetch-Site` or `Origin` header must match, so other websites open in your browser cannot write your files.
- **Uses an allowed host.** The `Host` must be localhost, an IP address, or listed in Vite's `server.allowedHosts`. This stops DNS rebinding, where an attacker's domain is pointed at your machine. The Vite plugin checks this itself, because Vite 5 and 6 run their own host check after plugin middleware.
- **Sends JSON.** `Content-Type: application/json` is required, which browsers cannot send across origins without a CORS preflight, and bodies over 1 MB are refused.

Non-browser tools such as `curl` send no `Origin` header and are allowed from an allowed host.

## What Gets Written

- **Keys** may not contain the segments `__proto__`, `prototype` or `constructor`.
- **Locales** must match `/^[a-zA-Z][a-zA-Z0-9_-]*$/`, so they cannot name a path.
- **Files** are chosen by the server from the key and locale, inside your translation roots. A client cannot pick the file.
- **Values** are written as JSON strings, which escapes them for the file. They are not HTML-sanitized: your i18n library decides how messages are rendered.

## What Is Never Overwritten

- A locale file that is not valid JSON is left untouched instead of being replaced.
- A key holding a group of keys, or plural variants, is not replaced by text.
- With `expected`, a value that changed since the editor loaded it is not overwritten; the save fails with HTTP 409.

The [Paraglide integration](/guides/sveltekit-paraglide/) also refuses edits that add inputs or markup a message does not have, and files with duplicate keys.

## Development Only

- The Vite and Webpack plugins run only in the dev server, so production builds have no endpoint.
- Render the editor only in development, for example with `import.meta.env.DEV`, so no editing code reaches production bundles.
- In production, a save request reaches no endpoint and fails.
